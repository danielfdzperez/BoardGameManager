# Idiomas (i18n)

Módulo `js/i18n.js` (global `I18n`, atajos `tr()` y `tv()`) + ficheros JSON en `i18n/`.

## Ficheros
- `i18n/idiomas.json` — lista de idiomas disponibles: `[{ "codigo": "es", "nombre": "Español" }, …]` (el nombre sale en el selector).
- `i18n/es.json`, `i18n/en.json` — un fichero por idioma, JSON anidado (`"filtros": { "limpiar": "Limpiar" }` → clave `filtros.limpiar`). Las claves que empiezan por `_` son metadatos.
- **`es.json` es el idioma base**: lo que falte en otro idioma se toma del español, así que una traducción puede ser parcial.

## Cómo elige el idioma
1. El que la persona eligió en el selector (se guarda en `localStorage`, clave `mesa_idioma`).
2. Si no, el del dispositivo (`navigator.languages`; en la app Android es el idioma del teléfono).
3. Si no hay coincidencia: inglés (o español si no existiera).
- **Web**: selector 🌐 en la esquina derecha de la cabecera (en móvil, arriba a la derecha). Cambiarlo recarga la página.
- **App Android**: sin selector, siempre el idioma del teléfono (`I18n` lo oculta si `Capacitor.isNativePlatform()`).

## Cómo añadir un idioma
1. Copiar `i18n/es.json` a `i18n/<código>.json` (p. ej. `fr.json`) y traducir los valores (no las claves). Mantener los `{marcadores}` y las etiquetas HTML (`<strong>`, `<code>`, `<a>`).
2. Añadir `{ "codigo": "fr", "nombre": "Français" }` a `i18n/idiomas.json`.
3. Si es la app: `powershell -File capacitor\sincronizar.ps1` y `npx cap sync android`.
No hay que tocar código.

## Uso en el código
- HTML: `data-i18n="clave"` (texto), `data-i18n-html="clave"` (con etiquetas), `data-i18n-attr="placeholder:clave;aria-label:otra"` (atributos). El texto español escrito en el HTML es solo el de reserva si el JSON no carga; **manda `es.json`**. Si un elemento contiene hijos (casillas, `<output>`…), envolver el texto en un `<span data-i18n>`.
- JS: `tr("clave", { n: 3, nombre: "x" })`. Marcadores `{nombre}`. Con `n` numérico se elige la forma plural `clave.one` / `clave.other` (reglas `Intl.PluralRules` del idioma; ver `jugadores` en `es.json`). Si falta la clave se ve la propia clave.
- `tv("modo", valor)`: traduce un **valor de los datos** si existe `valores.modo.<valor>` (hoy los modos de juego); si no, lo devuelve igual.
- Formato: `I18n.numero(n, decimales)`, `I18n.fecha(ms)`, `I18n.comparar(a, b)` (ordenar según el idioma). No usar `toFixed(...).replace(".", ",")` ni `localeCompare(..., "es")`.
- Las páginas deben esperar a `I18n.listo` (promesa) antes de pintar; `html:not(.i18n-listo) body` está oculto en CSS hasta entonces (a los 2 s se muestra aunque falle).
- Los textos **con HTML** que pasan por `innerHTML` son de confianza (vienen de los JSON); los datos del usuario se escapan siempre con `esc()`.

## Qué NO se traduce
Los datos de los juegos (nombres, descripciones, ambientaciones, mecánicas, categorías…) están en castellano tal como se guardaron, y los diccionarios `MECANICAS`/`CATEGORIAS` de `js/bgg.js` traducen de BGG al castellano. Los valores de `modo` ("Cooperativo", "Competitivo"…) se guardan en castellano (el asistente los compara) y solo se **muestran** traducidos con `tv`. Si se quisiera traducir también el contenido, habría que añadir `valores.<campo>.<valor>` para ambientación/mecánicas/categorías o guardar los datos por idioma.

## Requisito
Los textos se cargan con `fetch` de `i18n/*.json`: la web debe servirse por **http(s)** (GitHub Pages, `serverTest/iniciar.bat`, la app Capacitor). Abierta con doble clic (`file://`) Chrome bloquea el `fetch` y se ve el texto español del HTML; Firefox sí lo permite.
